# GeoPulse – SYNTHETIC dataset (simulated, not observed)

Every row is generated by `generate_geopulse_data.py` (seed 42). Each CSV has `Data_Source = SYNTHETIC`.
Area centres and postal codes are approximate and illustrative; store names, coordinates, footfall, sales and weather are invented.
Footfall and sales are generated from one model, so the footfall-sales correlation is built in. Do not present it as a finding. Present it as a demonstration of the method.

| File | Rows | Grain | Key columns |
|---|---|---|---|
| stores.csv | 60 | one row per store | Store_ID, Store_Name, Store_Category, Latitude, Longitude, City, Area, Postal_Code, Floor_Area_sqm, Opening_Date, Competitor_Store_Count (same category within 1 km), Nearby_POI_Count, Population_Density_per_sqkm |
| footfall_hourly.csv | 70,200 | store x hour (90 days, 09:00-21:00) | Location_ID, Store_ID, Timestamp, Visit_Date, Visit_Hour, Day_of_Week, Footfall_Count, Visitor_Count, Dwell_Time_min, Pedestrian_Count, Weather, Temperature_C, Is_Holiday |
| sales_hourly.csv | 70,200 | store x hour | Store_ID, Transaction_Date, Visit_Hour, Transactions, Quantity_Sold, Revenue_INR |
| transactions.csv | 383,235 | one row per transaction (last 30 days) | Transaction_ID, Store_ID, Transaction_Date, Visit_Hour, Product_Category, Quantity_Sold, Revenue_INR |
| weather_daily.csv | 90 | day | Visit_Date, City, Weather, Temperature_C, Rainfall_mm |

## Joins
- stores.Store_ID = footfall_hourly.Store_ID = sales_hourly.Store_ID = transactions.Store_ID
- footfall_hourly (Store_ID, Visit_Date, Visit_Hour) = sales_hourly (Store_ID, Transaction_Date, Visit_Hour)
- footfall_hourly.Visit_Date = weather_daily.Visit_Date

## Built-in patterns (so analysis has something to find)
Lunch and evening peaks; weekend and holiday uplift; rain lowers footfall; busier areas (MG Road, Indiranagar, Koramangala) outperform outer areas; conversion varies by category; stores with no same-category competitor within 1 km convert slightly better.

## Limits
Revenue is in INR and the basket model is simplistic. Dwell time and unique visitors are drawn from simple distributions. No real customer or location tracking is represented.
